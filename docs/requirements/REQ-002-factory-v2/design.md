# REQ-002：Factory V2 渐进自治设计

## 需求与成功标准

DUN 在首次三角龙需求完成后，需要把后续同类动物展品从多 Issue、多 PR、多次人工确认，升级为
以完整产品需求为单位的渐进自治流程。成功标准是：一个需求贯穿一个 Issue、一个分支和一个
Draft PR；内部工作可以细分但不增加流程对象；成熟 Pattern 能减少重复确认；实时状态和机器
证据由 GitHub 承载；人工仍掌握最终合并。

## 设计原则

- 完整产品结果是需求边界，工作量和变更数量不是边界。
- 第一项需求用于建立基线；后续 3 次连续干净执行可让同一 Pattern 从监督模式晋级可信模式。
- `autonomous` 作为未来级别保留在机读模型中，但本版禁用，不能自动合并或发布。
- 监督模式确认技术方案和产品验收；可信模式自动通过这两项，但不改变人工合并策略。
- 新能力、越出 Pattern、人工纠正、验证拒绝、逃逸缺陷或 Pattern 升版会触发降级或重新校准。
- 产品面向用户的语言策略保持中文为主、英文为辅；Agent 工作文档和 PR 使用中文；代码标识使用英文。
- 风险用语义范围、承重路径、Pattern 不变量、测试、Deep Gate 和独立验证控制。

## 信息结构

| 信息 | 唯一权威来源 |
|---|---|
| 产品需求、方案、决策、最终交付 | `docs/requirements/REQ-*/` |
| 实时执行状态 | GitHub Issue、标签、分支、Draft PR |
| 机器执行证据 | GitHub Checks、Issue/PR 的 V2 结构化评论 |
| 项目级策略 | `.factory/project.json` 与章程 |
| 可复用变化模式 | `.factory/patterns/*.json` |

V1 队列、状态、逐暂停记录与三角龙分阶段设计完整迁入归档，不再作为活跃控制面。

## 内部 work units

1. 用契约测试固定 V2 的关键不变量，并证明 V1 不满足。
2. 建立项目配置和 `animal-exhibit-v1` Pattern。
3. 重写共享契约、章程与 Claude/Codex 工作流。
4. 归档 V1 状态文档并建立需求级文档结构。
5. 增加 PR Deep Gate 与仓库侧收敛设置。
6. 执行新旧流程对照评测与 Deep Gate，创建一个中文 Draft PR 和候选交付。
7. 由全新上下文独立验证，确认最终证据后交由人类合并。

这些工作单元只用于提交、测试和断点恢复，不产生额外 Issue 或 PR。

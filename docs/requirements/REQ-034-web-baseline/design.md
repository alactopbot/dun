# REQ-034：简化网页版技术方案与开放性约束

状态：Draft，等待方案审核  
对应 Issue：[#34 简化网页版技术方案与开放性约束](https://github.com/alactopbot/dun/issues/34)  
执行路径：普通需求（Pattern：none）  
Gate：实现阶段 `deep`；本次仅 Spec 的 PR 使用 `fast`

## 1. 目标与完成结果

把 DUN 从“面向公开扩展、覆盖多类设备、每份素材都走完整可再分发流水线”的严格基线，收敛为一个
桌面 Web 优先、可以小步维护的互动博物馆。完成后：

- 正式支持基线是当前稳定版桌面 Chromium、1440×900 左右视口；其他现代浏览器、平板、手机和旧浏览器
  只做尽力可用，不是逐展品交付门槛；
- 技术方案保留现有 React、Three.js、服务端正文、单 Canvas、静态 poster 和安静体验架构，但不再规定
  横竖双套素材、五个视口、44px、200% 缩放、移动端性能、固定 FPS、复杂缓存、完整 DCC 流水线或
  阶段化入馆 SOP；
- “开放、公开 Issue、开放素材优先、必须允许公开再分发”不再是产品目标或素材选择评分项；首页、README、
  Agent 指南和 Factory 章程不再把它们描述为产品承诺；
- 新素材可以是自制、委托、商业或开放许可素材，只要 DUN 对仓库保存和实际网页交付拥有明确权利；
  不要求为内部原创素材保存提示词、候选哈希、逐步修改记录或统一 provenance 证据包；
- 第三方事实继续保留可核对的来源，第三方素材继续保留作者/来源、适用许可或使用凭证、必要署名；
  无来源或无网页交付权的素材仍不得使用；
- 当前三只动物、现有合法署名、既有许可证文本与来源证据原样保留，不因基线简化而删除或被重新解释；
- 相关验证器和测试只强制新的最小基线，不再通过旧断言把已删除的规范恢复成隐性要求。

## 2. 范围决定

### 2.1 浏览器与版面基线

唯一正式人工浏览器验收组合为当前稳定版桌面 Chromium、1440×900。实现应使用普通流式布局，避免主动
锁死页面滚动或造成明显横向溢出，但不为手机、平板、低高度横屏、超宽屏、旧浏览器或固定设备清单制作
专门布局和素材。

现有响应式 CSS、portrait 图片、键盘控制、减少动态效果和静态降级可以继续存在；本需求不为了“证明
简化”而删除已经正常工作的代码或资产。它们从全局完成条件降为可保留的既有能力，后续只有在具体
需求明确涉及这些行为时才需要专项验证。

静态 poster 仍是 WebGL 或模型加载失败时的简单回退，因为它直接降低网页版白屏风险；但不要求每个方向
各一张。新展品默认只需一张横版背景、一张 poster 和一份模型，缩略图按馆藏导航实际需要提供。

### 2.2 开放性与许可决定

本需求取消“开放”作为产品设计目标，但不把“无需开放”解释成“无需权利”。最低规则是：

- 自有素材只需确认 DUN 有权保存和用于网站，不强制选择 Creative Commons 许可；
- 第三方素材必须记录足以重新定位权利来源的信息，并证明许可覆盖仓库当前的公开保存方式和浏览器向
  访客发送文件的方式；许可要求署名时继续在页面或 credits 中署名；
- 商业或自定义许可可以使用，不再受 CC0/CC BY/CC BY-SA 白名单限制；如果许可只允许渲染成品、不允许
  仓库托管或向浏览器交付源资产，则不能把该源资产提交和发送；
- 哈希只用于运行时文件完整性、缓存版本和 poster 绑定，不再作为证明开放再分发权的替代品；
- 已经随当前公开仓库提供的 CC BY 模型及 CC BY-SA 内容继续遵守各自条款，不删除署名、来源和许可链接。

当前仓库是公开仓库，并已包含 `AGPL-3.0` 的代码和 `CC-BY-SA-4.0` 的原创内容。删除许可证文件不能撤销
已授予版本的权利，而且 Issue 未指定一个替代许可证。因此本需求明确 **不修改 `LICENSE` 和
`CONTENT-LICENSE.md`**；实现只把它们从“产品必须开放”的设计目标改述为“当前仓库材料适用的法律
声明”。若维护者要把未来版本改为专有许可，应另开完整需求，明确新许可、权利人、贡献历史、第三方
材料边界和生效版本。

### 2.3 儿童体验与内容底线

继续保留：面向 2–6 岁儿童和照护者、无账户、广告、行为追踪、自动播放、惊吓效果、竞争评分和运行时
AI。儿童可见事实仍需能定位到可靠来源；模型继续明确为艺术复原，不能当作事实来源。

不再把完整双语、固定事实数量、固定观察问题数量、键盘全功能控制、44×44px、200% 缩放和
`prefers-reduced-motion` 写成所有未来需求的统一硬门。具体功能若改变现有可见行为，应在自己的 Spec 中
说明要保留或改变什么。

## 3. 非目标

- 不删除现有三只动物的 portrait、poster、缩略图、manifest、evidence、署名或来源记录。
- 不替换模型、背景、教育事实、路由、Three.js 展示器、依赖、构建工具或 Cloudflare 运行时。
- 不承诺当前页面立即移除所有响应式、键盘或减少动态效果实现。
- 不把当前公开仓库改为私有，不重写 Git 历史，不尝试撤销历史版本已经授予的许可。
- 不为未来版本选择新的专有许可证，不对代码或素材权属作未经证据支持的结论。
- 不降低 Factory 的 Issue、Draft/Ready、Gate、独立验证、人工合并和不发布边界。
- 不在本需求中部署或发布网站。

## 4. 用户与维护者可见变化

- 首页导航的“开放计划”、页面中的“公开 Issue”承诺和页脚 `Open-source project` 改为中性的“项目说明”
  与网页版迭代说明；儿童博物馆的安静体验文案不变。
- README 不再称 DUN 为“开放式”或把公开 Issue/开放许可列为产品原则；保留一个“当前仓库许可”章节，
  如实链接现有许可文件和第三方材料规则。
- Agent 指南将“open museum”改为“web museum”，素材要求从完整 provenance/redistribution 证明收敛为
  事实来源与合法使用/必要署名可验证。
- Factory 章程仍把技术方案、许可、内容、素材和测试列为承重路径，但完成定义不再全局要求响应式、
  44px、减少动态效果、修改记录和运行时哈希全链路；只要求当前 Spec 选定的浏览器基线、合法素材和
  儿童体验边界。
- 现有页面的模型署名继续显示。许可证标签从硬编码的 `Creative Commons Attribution 4.0` 改为读取
  manifest 的许可名称，给未来商业或自定义许可留下合法表达入口。

## 5. 技术方案

### 5.1 重写技术基线

将 `docs/MUSEUM_TECHNICAL_PLAN.md` 原子替换为一份短方案，保留以下章节：

1. 产品目标与最低不变量；
2. 现有 Web 技术栈和支持基线；
3. React/Three.js/静态 poster 的职责边界；
4. 最小展品数据与素材包；
5. 第三方事实和素材的最低权利记录；
6. 简单的模型接入步骤；
7. 当前桌面 Chromium 浏览器验收、构建和测试；
8. 失败回退、风险与按需扩展规则。

删除原方案中的候选 100 分评分、固定许可白名单、横竖构图像素规范、提示词/候选/编辑哈希、固定 Blender
步骤、完整运行时预算表、五视口矩阵、逐层缓存与 GPU 回收清单、CI 脚本路线图、四阶段扩展计划、22 步
入馆 SOP，以及把响应式、开放发布和全 provenance 设为统一完成条件的内容。

### 5.2 最小素材契约

`scripts/assets/validate.mjs` 继续验证真实网页运行需要的完整性，但移除策略性硬编码：

- 保留：文件存在、路径唯一、字节数和运行时 SHA-256 匹配、URL 缓存版本匹配、poster 与模型/
  presentation 未过期、自包含 glTF 2.0、Khronos error、危险或无关场景节点；
- 移除：每只动物必须正好六份资产、必须有 portrait、固定三个 Sketchfab UID、只允许 CC 白名单、
  `redistributionApproved === true`、四份 evidence 文件、固定 20/23 MiB/250k/24 等全局发布硬门；
- 新增最小权利字段兼容层：第三方模型需要 `creator`、`title`、`source`、`license` 和必要的
  `attribution`，自有素材可用明确的 `owner: "DUN"`；自定义许可可记录许可名称和内部/公开凭证位置；
- 为避免本次扩大到素材迁移，现有 manifest 格式继续有效，不批量删除字段。未来新格式应向后兼容，
  直到具体素材需求决定是否迁移旧包。

GLB 完整性错误继续 fail closed；尺寸、三角形、draw call 和纹理大小改为接入时人工观察或按具体需求
设置，不由本全局方案统一规定。

### 5.3 测试语义调整

- `tests/triceratops-style.test.mjs` 保留无远程 CSS、无无限动画、页面不锁滚动和英文内容不隐藏等简单
  安全断言；移除 44px、移动端 media query 和 reduced-motion 必须存在的全局规范断言。
- `tests/museum-assets.test.mjs` 保留当前三只模型的真实作者/来源/许可回归和完整性校验，但不再断言
  `redistributionApproved`、固定 CC 白名单、portrait 资产数量或纵向移动视口是全局发布条件；相机回归
  改用桌面基线画布，预览测试只验证所声明输出的完整轮廓。
- 增加或调整首页 SSR 断言，证明页面不再显示“开放计划”“公开 Issue”或 `Open-source project`，同时
  继续显示安静、无输赢、亲子共同观察的产品承诺。
- Factory 治理测试继续原样通过；不得通过删除 tests 或跳过 Gate 完成语义调整。

## 6. 影响范围

- `docs/MUSEUM_TECHNICAL_PLAN.md`：重写为精简 Web 基线。
- `AGENTS.md`：同步项目上下文、素材与验收边界。
- `docs/factory/CHARTER.md`：同步 NEEDS_SPEC、NEVER_AUTOMATE 和 DONE，不改变 Factory 授权模型。
- `README.md`：同步项目定位、原则与当前仓库许可说明。

- `app/exhibits/[slug]/page.tsx`：显示 manifest 中的实际许可名称，不硬编码 CC BY 4.0 标签。
- `scripts/assets/validate.mjs`：从开放再分发流水线收敛为运行完整性与最低使用权验证。

## 7. 必须保持的不变量

- 现有 `/` 和三个 `/exhibits/:slug` 路由继续构建并服务端输出主要正文。
- 页面无账户、广告、行为追踪、自动播放、惊吓效果、竞争评分和运行时 AI。
- 当前三只模型的作者、来源、CC BY 4.0、署名和修改说明继续准确显示；既有 CC BY-SA 内容声明不删除。
- 新第三方素材没有明确的网站使用与交付权时仍 fail closed；商业许可不是自动批准，也不是自动拒绝。
- 模型文件损坏、外部依赖缺失、哈希失配或 poster 失配仍不能通过资产校验。
- 模型不是科学证据，儿童事实仍有可核对的机构或研究来源。
- 当前正常工作的响应式、键盘、reduced-motion 和降级代码不因本需求被主动破坏。
- Factory 的普通 Spec、可信 Ready、Deep Gate、独立验证和最终人工合并边界不变。

## 8. 实现顺序

1. 先增加失败断言，证明首页、技术方案、Charter、样式测试和资产校验仍强制旧开放/多端基线。
2. 原子重写技术方案，并同步 AGENTS、README 和 Charter，避免同一提交出现相互矛盾的权威文本。
3. 更新首页开放性文案和实际许可标签渲染，不改变展品正文、素材或交互。
4. 收敛资产验证器；用真实当前素材证明旧 manifest 仍兼容，并用最小测试证明自有/自定义许可不因
   非 CC 而自动失败、缺少使用权信息仍失败。
5. 更新样式、资产与 SSR 测试语义；确认删除旧断言不会删除安静体验、来源、文件完整性和构建保护。
6. 运行针对性测试、`npm test` 和 `./.factory/scripts/gates.sh deep`。
7. 由隔离的新 Agent 对 Issue、当前 Spec、完整 diff、测试语义变化和当前 SHA 做独立验证。

## 9. 测试与验收标准

- 技术方案不再包含横竖双套、五视口、44px、200% 缩放、移动端性能、固定 FPS、CC 白名单、完整
  provenance、评分表或 22 步 SOP 等统一硬门。
- AGENTS、README、Charter、首页和技术方案对“网页版桌面优先、开放不是产品目标、合法使用仍是底线”
  的表述一致。
- 首页在 SSR HTML 中不出现“开放计划”“公开 Issue”或 `Open-source project`，仍包含 DUN、三角龙、
  “没有输赢”和亲子安静体验信息。
- 当前三只展品和首页均返回 200；现有内容、来源、导航、单 Canvas、poster 回退和无运行时第三方请求
  的相关测试继续通过。
- 当前三只模型文件、哈希、poster 绑定、GLB 完整性、作者、来源、许可和署名继续通过校验。
- 验证器不再因为合法素材采用自有或自定义商业许可而自动失败，但缺少权利来源/必要署名时仍失败。
- 样式测试不再把手机 media query、44px 或 reduced-motion 作为所有未来实现的 Gate；页面不锁滚动、
  不隐藏英文、无远程 CSS 和无限动画的断言保留。
- `LICENSE` 与 `CONTENT-LICENSE.md` 字节不变；PR 明确说明没有撤销或替换历史/当前许可。
- Deep Gate GREEN，当前 SHA 的独立验证接受，最终是否合并仍由人类决定。

## 10. 风险与回滚

- **移动端体验退化**：本需求不主动删除现有适配，只取消未来统一承诺；若真实用户需要手机支持，单独
  建立有设备范围和证据的需求，而不是恢复模糊的全平台门槛。
- **把宽松许可规则误当成无许可规则**：验证器仍要求第三方权利来源和必要署名，Spec 明确浏览器交付
  本身需要授权；独立验证重点检查非 CC 分支是否 fail closed。
- **公开仓库与商业素材冲突**：任何不允许公开仓库保存的资产都不能提交到当前仓库；应改用允许公开
  托管的许可、私有交付机制或另一个经批准的仓库/部署方案。
- **许可文案造成误解**：README 使用“当前仓库许可”而非“开放产品目标”，并保持两个许可证文件不变；
  未来重许可必须另走权利审查。
- **删除测试掩盖真实回归**：实现只修改本 Spec 点名的断言，保留路由、内容、来源、模型完整性、构建与
  儿童体验测试，并由 Deep Gate 和独立验证审查完整 diff。
- **精简文档遗漏关键运行知识**：新技术方案必须保留现有架构、最小素材契约、加载失败回退、接入步骤
  和本地命令；删除的是全局强制细节，不是让实现无法维护。

回滚时应把技术方案、AGENTS、Charter、README、首页文案、验证器和测试作为一个原子集合恢复，不能只
恢复旧测试却保留新方案，或只恢复开放文案却保留宽松资产规则。现有素材和许可证文件无需回滚，因为
本需求不修改它们。
